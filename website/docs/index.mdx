## A service, then a component

No state declarations for individual fields. No React imports in your service. The build-time compiler handles render tracking so your component can stay straightforward.

```tsx title="Counter.tsx"
import { Service } from '@kinstate/core';
import { ServiceProvider, useService } from '@kinstate/react';

class CounterService extends Service {
  count = 0;

  increment() {
    this.count++;
  }

  get doubled() {
    return this.count * 2;
  }
}

function Counter() {
  const counter = useService(CounterService);

  return (
    <button onClick={() => counter.increment()}>
      {counter.count} · doubled: {counter.doubled}
    </button>
  );
}

export default function App() {
  return (
    <ServiceProvider services={[CounterService]}>
      <Counter />
    </ServiceProvider>
  );
}
```

:::important The compiler is part of the setup
Kinstate requires its Babel or Vite plugin. A hook alone cannot track arbitrary property reads after it returns. [Set up your build](./guide/quick-start.md) before using `useService`.
:::

## A small public surface

| In a service | In React | At build time |
| --- | --- | --- |
| `Service`, `dependencies`, `observe` | `ServiceProvider`, `useService` | `@kinstate/compiler` |
| Plain classes and computed getters | Scoped instances and tracked reads | Explicit per-render instrumentation |

The core works independently of React. The React integration uses supported external-store APIs, and the compiler adds tracking around the reads you author. Read [the introduction](./guide/introduction.md) for the model, or go straight to [the API reference](./reference/core.md).

## Know the boundaries

Kinstate observes plain objects and arrays owned by a service. External input objects remain immutable borrowed references. Native collections and custom nested classes are opaque; JavaScript private slots do not become observable. Whole-array processing still has real costs.

[Read the limits and trade-offs](./guide/limitations.md) and [performance guidance](./guide/performance.md) before choosing how to store a large dataset.
